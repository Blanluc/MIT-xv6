Q : What was the previous mode that the CPU was in?
A : (200000022)16 = (001000000000000000000000000000100010)2
    SPP (bit 8) = 0 → previous mode was user mode
    SPIE (bit 5) = 1 → interrupts were enabled in the previous mode
    SIE (bit 1) = 1 → supervisor interrupts currently enabled
    the CPU was previously in user mode, which makes sense since init issued an ecall from user space to invoke the open syscall.

    kernel.asm :

        80001d08:	00002683          	lw	a3,0(zero) # 0 <_entry-0x80000000>

Q : Why does the kernel crash? Hint: look at figure 3-3 in the text; is address 0 mapped in the kernel address space? Is that confirmed by the value in scause above?
A : scause=0xd => d = 13 : Load page fault
    address 0 is not mapped!
    The scause register indicates the type of the page fault and the stval register contains the address
    that couldn’t be translated.
    scause=0xd sepc=0x80001d08 stval=0x0

    Looking at figure 3-3, the kernel virtual address space starts at 0 on the left side but there are no 
    mappings at address 0 — the lowest mapped region is PLIC at 0x0C000000. So address 0x0 is indeed 
    unmapped in the kernel virtual address space.
